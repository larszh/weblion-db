# Sprachen und Übersetzungen

Die Console gibt es auf Deutsch, Englisch, Französisch, Italienisch und Niederländisch. Deutsch ist die
Ausgangssprache: Jeder Text entsteht zuerst auf Deutsch, Englisch kommt im selben Schritt dazu, die anderen
drei Sprachen folgen. Alle Texte liegen im Code, Änderungen aus dem Admin-Bereich liegen in der Datenbank und
gelten ohne Deploy.

Die KI-Funktionen, mit denen sich Texte übersetzen lassen, beschreibt [ai.md](ai.md).

## Sprachen und Rückfall

| Sprache (wie in der Auswahl) | Code | Format (Zahlen, Daten) | Flagge |
| ---------------------------- | ---- | ---------------------- | ------ |
| Deutsch                      | `de` | `de-CH`                | DE     |
| English                      | `en` | `en-GB`                | GB     |
| Français                     | `fr` | `fr-CH`                | FR     |
| Italiano                     | `it` | `it-CH`                | IT     |
| Nederlands                   | `nl` | `nl-NL`                | NL     |

Fehlt ein Text in Französisch, Italienisch oder Niederländisch, zeigt die Console den englischen, sonst den
deutschen. Fehlt er auf Englisch, zeigt sie den deutschen. Englisch ist immer vollständig, das prüfen die
Tests. In der Auswahl steht jede Sprache mit ihrem eigenen Namen und einer Flagge (Deutsch mit DE, nicht CH).

Welche Sprache jemand sieht:

- **Angemeldet:** die Sprache im Profil (Mein Konto > Sprache, auch im Benutzermenü). Sie wird beim Benutzer
  gespeichert und gilt auf jedem Gerät.
- **Vor der Anmeldung:** die Wahl auf der Anmeldeseite, sonst die erste passende Sprache des Browsers, sonst
  Englisch. Auf der Seite einer Einladung wird die gewählte Sprache die Sprache des neuen Kontos.
- **E-Mails** an eine Person gehen in ihrer Sprache. Eine Einladung an jemanden ohne Konto geht in der
  Sprache der Person, die einlädt.
- **Rechnungen, Zahlungserinnerungen und Zahlungsbestätigungen** gehen in der "Sprache für Rechnungen" im
  Abrechnungsprofil des Kunden, ohne eigene Wahl in der Sprache des Owners. Eine ausgestellte Rechnung behält
  ihre Sprache. Zahlen und Daten auf der Rechnung bleiben in jeder Sprache im Schweizer Format.
- **Produkte** haben Name und Beschreibung in den vier weiteren Sprachen (Produktformular, Abschnitt
  "Übersetzungen"; leer gelassen gilt der deutsche Text). Neue Positionen aus Produkten bekommen den Text in
  der Sprache der Rechnung. Bestehende Positionen bleiben, wie sie erfasst sind.

## Wo die Texte liegen

| Was                        | Wo                                                                           |
| -------------------------- | ---------------------------------------------------------------------------- |
| Texte                      | `packages/shared/src/i18n/sections/<Abschnitt>.<Sprache>.ts`                 |
| Stempel (siehe unten)      | `packages/shared/src/i18n/stamps/<Sprache>/<Abschnitt>.json`                 |
| Ausnahmen der Prüfungen    | `packages/shared/src/i18n/allowlists/<fr, it oder nl>/<a, b oder c>.ts`      |
| Begriffe (Standard)        | `packages/shared/src/i18n/glossary.ts`                                       |
| Prüfungen                  | `packages/shared/src/i18n/checks.ts`, Tests in `i18n.test.ts`                |
| Änderungen aus dem Admin   | Tabellen `translation_overrides`, `translation_glossary`, `translation_jobs` |
| Stilhinweise aus dem Admin | Tabelle `settings`, Zeile `i18n_style`                                       |

Es gibt 16 Abschnitte: `core`, `admin`, `ai`, `translations`, `email`, `pdf`, `hosting`, `cloudflare`,
`websites`, `mail`, `billing`, `cloud`, `storage`, `phone`, `media`, `uptime`. Die Reihenfolge der
Schlüssel im deutschen Abschnitt ist die Reihenfolge überall, auch im Admin-Bereich. `email` und `pdf` (E-Mails
und Rechnungs-PDF) braucht nur der Server, sie kommen nie in den Browser. Im Web ist ein Schlüssel vom Typ
`TranslationKey` (14 Abschnitte), im Server vom Typ `ServerTranslationKey` (alle 16). Ein unbekannter
Schlüssel ist ein Fehler beim Typecheck.

Die Texte des Rechnungs-PDF (`pdf`) dürfen nur Zeichen aus Windows-1252 enthalten, weil das PDF die
Standardschriften nutzt.

## Neue Texte hinzufügen

1. Den deutschen Text in `sections/<Abschnitt>.de.ts` eintragen, den englischen mit demselben Schlüssel in
   `sections/<Abschnitt>.en.ts`. Beide gehören in denselben Commit.
2. Die Stempel für Englisch schreiben:

   ```bash
   pnpm --filter @weblion/api i18n:stamp --locale en --section <Abschnitt>
   ```

3. Französisch, Italienisch und Niederländisch dürfen fehlen. Bis jemand sie übersetzt, zeigt die Console
   dort den englischen Text. Übersetzt wird entweder direkt in `sections/<Abschnitt>.<fr|it|nl>.ts` (danach
   `i18n:stamp --locale <Sprache> --section <Abschnitt>`) oder unter Admin > Übersetzungen und dann zurück in
   den Code (siehe [Zurück in den Code](#zurück-in-den-code)).
4. Fehlende und veraltete Texte zeigt:

   ```bash
   pnpm --filter @weblion/api i18n:report              # alle Sprachen, Zahlen pro Abschnitt
   pnpm --filter @weblion/api i18n:report --locale fr --missing
   pnpm --filter @weblion/api i18n:report --stale
   ```

   `i18n:report` endet immer mit 0, ausser bei einem falschen Argument. CI druckt den Bericht bei jedem Lauf.

Im Web kommt ein Text mit `t('schlüssel')` aus `useI18n()`, Platzhalter in geschweiften Klammern
(`{name}`) füllt `t('schlüssel', { name })`.

## Veraltete Übersetzungen

Ein Stempel hält pro Schlüssel fest, gegen welchen deutschen Text eine Übersetzung geschrieben wurde (zwei
Prüfsummen: deutscher Text und Übersetzung). Ändert sich der deutsche Text, ist die Übersetzung "Veraltet",
bis jemand sie nachführt oder bestätigt. Die Console zeigt sie trotzdem an, ausser bei
[Rechtstexten](#rechtstexte).

- Wer einen deutschen Text ändert, ändert den englischen mit und stempelt Englisch neu. Englisch muss immer
  aktuell sein, sonst schlägt der Test fehl.
- Eine geänderte Übersetzung stempelt `i18n:stamp` gegen den aktuellen deutschen Text.
- Passt eine Übersetzung auch zum neuen deutschen Text, bestätigt `--confirm` sie als aktuell, zum Beispiel
  `i18n:stamp --locale fr --key <Schlüssel> --confirm`. Ohne `--section` oder `--key` fragt `--confirm` im
  Terminal nach, ausser mit `--yes`.
- `i18n:stamp --check` schreibt nichts und endet mit 1, wenn eine Datei anders werden würde.

Die Stempel beschreiben nur den Code, nie die Datenbank. Änderungen aus dem Admin-Bereich haben ihre eigene
Prüfsumme in `translation_overrides`.

## Übersetzungsregeln

Diese Regeln gelten für alle, die übersetzen: im Code, im Admin-Bereich, in einer Datei für Übersetzer und für
Claude beim Übersetzen mit KI. Was sich maschinell prüfen lässt, prüfen die
[Prüfungen](#prüfungen).

1. **Höflich anreden.** Deutsch "Sie", Französisch "vous" (auch im Imperativ: "Cliquez", "Saisissez"),
   Italienisch "Lei" (gross, wenn es allein steht; "le inviamo", "il suo account" klein), Niederländisch "u"
   und "uw" (klein), Englisch neutral "you". Nie tu, du, jij oder je.
2. **Für Leser in der Schweiz.** Französisch und Italienisch für die Schweiz (fr-CH, it-CH): "TVA" und "IVA"
   für MWST, "facture" und "fattura", im Französischen "e-mail" statt "courriel", die offiziellen Begriffe der
   QR-Rechnung ("QR-facture", "section paiement"; "QR-fattura", "sezione pagamento"; "QR-bill", "payment
   part"). Niederländisch ist Standardniederländisch (nl-NL). Englisch behält die Schreibweise der bestehenden
   Texte ("organization", "finalize"). Beträge, Daten und Zahlen nie in den Text schreiben, sie kommen
   formatiert über Platzhalter.
3. **Knöpfe und Beschriftungen kurz halten**, höchstens etwa ein Drittel länger als Deutsch. Knöpfe im
   Infinitiv ("Enregistrer", "Opslaan"), Italienisch in der üblichen Kurzform ("Salva", "Annulla",
   "Elimina"), ohne Punkt am Ende. Kein Titelstil: im Englischen "Save changes", nicht "Save Changes".
4. **Platzhalter und Zeilenumbrüche wie im Deutschen.** Jeder `{name}` gleich oft, nie übersetzt oder
   umbenannt, nur verschoben, wo die Grammatik es verlangt. Jeder Zeilenumbruch bleibt.
5. **Französische Leerzeichen.** Ein geschütztes Leerzeichen (U+00A0) vor ":" und "%", kein Leerzeichen vor
   "?", "!" und ";".
6. **Gerade Anführungszeichen** ("...") in allen Sprachen, nie typografische oder spitze. Gerade
   Apostrophe ("l'adresse", "dell'account").
7. **Kein scharfes S**, auch nicht im Deutschen (Schweizer Schreibweise: "Grüsse", "schliessen").
8. **Kein langer Gedankenstrich** (U+2014). Stattdessen Komma, Doppelpunkt oder Klammern. Der kurze Strich
   (U+2013) bleibt nur dort, wo ihn der deutsche Text hat.
9. **Ein Begriff, eine Übersetzung.** Die Begriffe unten und das Glossar im Admin-Bereich sind verbindlich.
   Derselbe deutsche Begriff bekommt in jedem Abschnitt dieselbe Übersetzung.
10. **Namen bleiben Namen.** Produkt-, Provider- und Protokollnamen werden nie übersetzt (Liste unten).
    Technische Angaben im Text (Typen von DNS-Einträgen, Pfade, JSON-Beispiele, Namen von Berechtigungen)
    bleiben, wie sie sind.
11. **Satzzeichen des Originals.** Die Auslassungspunkte in Suchfeldern ("Suchen…", "Rechercher…"), den
    Doppelpunkt am Ende einer Beschriftung, das Fragezeichen eines Bestätigungstitels und die Klammern
    behalten.
12. **Rechtstexte wörtlich.** `ai.notice.title` und `ai.notice.text` vollständig und Satz für Satz
    übersetzen, nichts kürzen, nichts dazufügen. Sie werden nie maschinell übersetzt.
13. **Übersetzen, nicht schreiben.** Keine Erklärungen, keine neuen oder weggelassenen Sätze, keine Links,
    E-Mail-Adressen oder Zahlen, die der deutsche Text nicht hat. E-Mails im üblichen Briefstil der Sprache:
    "Bonjour" und "Meilleures salutations", "Buongiorno" und "Cordiali saluti", "Goedendag" und "Met
    vriendelijke groet", "Hello" und "Kind regards". Die Markierung des Rechnungsentwurfs
    (`pdf.invoice.draftMark`) steht in jeder Sprache in Grossbuchstaben.

## Admin > Übersetzungen

Unter Admin > Übersetzungen (`/admin/translations`) sehen Mitarbeitende alle Texte in allen fünf Sprachen.
Ansehen braucht `platform:i18n:read` (Superadmins und Support), Ändern `platform:i18n:write` (nur
Superadmins). Jede Änderung gilt sofort und ohne Deploy: für E-Mails und PDFs gleich (weitere Prozesse der API
nach spätestens 15 Sekunden), im Browser beim nächsten Laden der Console. Jede Änderung steht im Audit-Log
(`i18n.override_update`, `i18n.override_revert`, `i18n.override_review`, `i18n.override_confirm`,
`i18n.glossary_*`, `i18n.style_update`, `i18n.import`, `i18n.cleanup`, `i18n.job_*`).

Die Seite hat fünf Tabs.

**Übersicht.** Pro Sprache: wie viele Texte übersetzt, aktuell, veraltet und fehlend sind und wie viele von
der KI stammen und ungeprüft sind, mit "Fehlende anzeigen" und "Veraltete anzeigen". Ist ein Rechtstext in
einer Sprache nicht aktuell, steht hier eine Warnung. Hier starten "Mit KI übersetzen" für die ganze Console
und "Aufräumen".

**Texte.** Jeder Schlüssel mit seinen fünf Zellen. Filter:

- **Suche:** Schlüssel oder Text in einer der fünf Sprachen, ohne Rücksicht auf Akzente und Gross- und
  Kleinschreibung. Sieht die Suche wie ein Schlüssel aus (`billing.invoice`), kommen die Schlüssel, die so
  beginnen, zuerst.
- **Sprache:** eine Sprache oder "Alle Sprachen".
- **Zustand:** "Alle", "Unübersetzt" (fehlt), "Veraltet", "Geändert" (im Admin-Bereich geändert, also noch
  nicht im Code), "Von KI", "Ungeprüft" (von der KI und noch nicht geprüft), "Braucht Aufmerksamkeit" (fehlt,
  veraltet, ungeprüft oder mit Hinweisen der Prüfungen).
- **Bereich:** der erste Teil des Schlüssels, zum Beispiel `billing` oder `ai`.

Die Filter stehen in der Adresse, ein Link zeigt also genau diese Auswahl. "Mit KI übersetzen" auf diesem Tab
übersetzt die aktuelle Auswahl.

**Eine Zelle bearbeiten.** Der Editor zeigt den deutschen Text, die englische Referenz und die Platzhalter.
Strg+Enter speichert, Esc bricht ab. Platzhalter, Zeilenumbrüche, scharfes S und langer Gedankenstrich prüft
die Console beim Speichern hart: Stimmt etwas nicht, speichert sie nicht. Die übrigen Prüfungen erscheinen als
Hinweise. Französische Leerzeichen korrigiert sie selbst und sagt es. Weiter gibt es:

- "Geprüft" als Häkchen, "Als geprüft markieren" und "Als ungeprüft markieren"
- "Auf Text aus dem Code zurücksetzen": löscht die Änderung, danach gilt wieder der Text aus dem Code
- "Als aktuell bestätigen" bei einer veralteten Übersetzung, die zum neuen deutschen Text passt
- "KI-Vorschlag": schlägt eine Übersetzung vor, die dieselben Prüfungen bestanden hat (braucht
  `platform:ai:use` und eingeschaltete KI, zählt zum Budget und zu den Limits der Person, nicht für
  Rechtstexte)

Auch der deutsche Text lässt sich hier ändern. Dann werden alle Übersetzungen dieses Schlüssels veraltet.

Die Zeichen in den Zellen: "Fehlt", "Veraltet", "Manuell", "KI, ungeprüft", "KI, geprüft", "Rechtstext",
"Nicht sichtbar" (eine Änderung, die gerade nicht gilt, etwa eine veraltete Übersetzung eines Rechtstexts)
und die Zahl der Hinweise.

**Glossar.** Die Begriffe aus der Tabelle oben ("Standard") und eigene Begriffe: deutscher Begriff,
Übersetzung pro Sprache oder "Nie übersetzen", Hinweis. Das Glossar gilt für das Übersetzen mit KI und für
die Prüfungen beim Speichern. Darunter die **Stilhinweise** pro Sprache: feste Standardhinweise (Anrede,
Schweizer Begriffe) und eigene Ergänzungen bis 2000 Zeichen, zum Beispiel zur Wortwahl. Sie gelten nur für
das Übersetzen mit KI.

**KI-Aufträge.** Die Aufträge von "Mit KI übersetzen", siehe unten.

**Import und Export.** Siehe [Zurück in den Code](#zurück-in-den-code).

**Aufräumen** (auf der Übersicht) löscht Änderungen zu Schlüsseln, die es nicht mehr gibt, Änderungen, die
inzwischen gleich im Code stehen, und die Übersetzungen aus dem Demo-Modus.

## Mit KI übersetzen

"Mit KI übersetzen" (Mass Translate) übersetzt viele Texte auf einmal mit Claude. Es braucht
`platform:i18n:write` und `platform:ai:use`, standardmässig also einen Superadmin, und eingeschaltete KI mit
der Funktion "Übersetzungen" (siehe [ai.md](ai.md#schalter)).

1. **Auswahl.** Sprachen (vorgewählt Französisch, Italienisch und Niederländisch, Englisch geht auch) und
   welche Texte: "Nur unübersetzte", "Nur veraltete", "Unübersetzte und veraltete" oder "Alle Texte der
   aktuellen Auswahl". Manuell geänderte und geprüfte Übersetzungen bleiben, ausser mit "Auch manuell
   geänderte und geprüfte Übersetzungen ersetzen". Rechtstexte übersetzt die KI nie.
2. **Kosten schätzen.** Die Console zeigt Anzahl Texte und Pakete, die geschätzten Kosten, das Modell, wie
   viele Übersetzungen bleiben, wie viele Rechtstexte ausgelassen werden und das verbleibende KI-Budget des
   Monats. Reicht das Budget voraussichtlich nicht, warnt sie.
3. **Übersetzung starten.** Die Console rechnet die Schätzung neu. Liegt sie mehr als 25 % über der
   bestätigten, fragt sie nochmals. Es läuft immer nur ein Auftrag auf einmal. Ist das Budget schon
   aufgebraucht, startet keiner.

Ein Auftrag läuft im Hintergrund weiter, auch wenn niemand die Seite offen hat. Er schickt Pakete von bis zu
50 Texten oder 8000 Zeichen an Claude, mit dem Modell der KI-Seite und dem Aufwand "medium", standardmässig 2
Pakete gleichzeitig (`I18N_AI_CONCURRENCY`, 1 bis 4). Jede Übersetzung durchläuft die
[Prüfungen](#prüfungen), hier ist jede ein harter Fehler, dazu: keine neuen Links, E-Mail-Adressen oder
Zahlen. Was eine Prüfung nicht besteht, geht einmal mit dem Grund zurück an Claude. Besteht es dann wieder
nicht, gilt der Text als fehlgeschlagen. Ergebnisse werden als "KI, ungeprüft" gespeichert und gelten sofort
für alle. Eine Zelle, die jemand während des Auftrags von Hand ändert, überspringt der Auftrag.

Der Auftrag stoppt,

- sobald er mehr als das 1.5-fache seiner Schätzung gekostet hat,
- wenn das KI-Budget des Monats aufgebraucht ist (das Budget teilen sich alle KI-Funktionen; danach sind auch
  die übrigen bis Monatsende gesperrt),
- wenn drei Pakete hintereinander ohne einen gespeicherten Text bleiben,
- wenn die KI ausgeschaltet wird, der Demo-Modus wechselt oder Anthropic den Schlüssel oder das Konto ablehnt.

Fertige Pakete bleiben in jedem Fall gespeichert. "Auftrag abbrechen" verwirft nur das laufende Paket.
"Fehlgeschlagene erneut versuchen" startet einen neuen Auftrag nur mit den fehlgeschlagenen Texten, mit
eigener Schätzung. Die Liste der Aufträge zeigt Fortschritt, Kosten gegen Schätzung, Tokens und die
fehlgeschlagenen Texte mit Grund.

**Kosten.** Für die ganze Console in Französisch, Italienisch und Niederländisch (rund 4600 Texte pro
Sprache, 279 Pakete) schätzt die Console mit Claude Opus 5.5 etwa USD 13. Was ein Lauf wirklich kostet, hängt
von der Länge der Antworten ab. Rechnen Sie mit USD 10 bis 20. Mit Claude Sonnet 5.5 kostet es etwa die
Hälfte. Rechenbeispiele in [ai.md](ai.md#was-eine-anfrage-kostet).

**Demo-Modus.** Ohne Schlüssel und mit `ENABLE_DEMO_PROVIDER=true` speichert ein Auftrag den deutschen Text
mit dem Sprachcode davor, zum Beispiel "[FR] Speichern", und kostet nichts. So lässt sich der Ablauf zeigen.
Diese Texte zeigt die Console nur im Demo-Modus. Sie werden gelöscht, sobald auf der KI-Seite ein echter
Schlüssel gespeichert wird, und "Aufräumen" löscht sie ebenfalls.

**Mehrere Prozesse.** Ein Auftrag läuft in dem Prozess der API, der ihn zuerst übernimmt. Eine Sperre in der
Datenbank sorgt dafür, dass immer nur einer daran arbeitet. Weitere Prozesse der API setzen
`I18N_JOB_ENABLED=false` (Standard `true`). Hält der Prozess normal an, geht der Auftrag zurück in die
Warteschlange. Nach einem Absturz übernimmt ihn der nächste Prozess mit eingeschalteten Aufträgen nach etwa
zwei Minuten.

## Zurück in den Code

Änderungen aus dem Admin-Bereich sollen in den Code zurück, damit sie mit dem nächsten Deploy im
Repository stehen.

1. **Exportieren** unter Import und Export: "Änderungen exportieren (JSON)" für alle Änderungen, oder "Sprache
   für Übersetzer exportieren (JSON)" für eine Sprache, auf Wunsch "Nur fehlende und veraltete Texte".
2. **Übernehmen** im Repository:

   ```bash
   pnpm --filter @weblion/api i18n:apply weblion-i18n-overrides-2026-11-07.json --dry-run
   pnpm --filter @weblion/api i18n:apply weblion-i18n-overrides-2026-11-07.json
   ```

   `--locale <Sprache>` nimmt nur eine Sprache, `--only-reviewed` nur geprüfte Texte. Jeder Wert läuft durch
   dieselben Prüfungen wie beim Speichern: Platzhalter, Zeilenumbrüche, scharfes S, langer Gedankenstrich und
   französische Leerzeichen sind harte Fehler (der Wert wird nicht übernommen, das Skript endet mit 1), die
   übrigen erscheinen als Warnung. Die Stempel der berührten Dateien schreibt das Skript gleich mit. Eine
   veraltete Änderung bleibt veraltet, eine bestätigte wird aktuell.

3. **Prüfen, committen, deployen** wie jede Änderung (`pnpm test`).
4. **Aufräumen** nach dem Deploy: Die übernommenen Änderungen stehen jetzt gleich im Code, "Aufräumen" auf der
   Übersicht löscht sie aus der Datenbank.

Der **Import** nimmt eine Datei in einem der beiden Formate wieder auf, zum Beispiel von externen Übersetzern.
"Prüfen" zeigt zuerst, was neu, geändert, unverändert und übersprungen wäre, "Importieren" übernimmt es.
Manuell geänderte Übersetzungen bleiben, ausser mit "Manuell geänderte Übersetzungen ersetzen". Mit
"Importierte Texte als geprüft markieren" gelten sie als geprüft. Übersprungen werden unbekannte Schlüssel,
Werte mit falschen Platzhaltern oder verbotenen Zeichen und KI-Texte für Rechtstexte. Import und Export gehen
je 10 Mal pro Minute und Person.

## Prüfungen

Dieselben Prüfungen laufen an fünf Stellen: im Test über die Texte im Code, beim Speichern einer Zelle, beim
Import, in `i18n:apply` und bei jeder Übersetzung durch die KI.

| Nr. | Prüfung                  | Regel                                                                                                                            | Sprachen           |
| --- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| 1   | Schlüssel                | Englisch hat genau die deutschen Schlüssel, die anderen keinen zusätzlichen; kein Schlüssel in zwei Abschnitten                  | alle               |
| 2   | Platzhalter              | dieselben `{name}` gleich oft und gleich viele Zeilenumbrüche wie im Deutschen                                                   | en, fr, it, nl     |
| 3   | Deutsch übrig            | kein ä, kein ö oder ü (ausser Niederländisch), nicht zwei typisch deutsche Wörter, keine unveränderte Kopie des deutschen Satzes | fr, it, nl         |
| 4   | Anrede                   | keine Du-Form (tu, te, toi, ton, ta, tes, t'; tu, ti, tuo, tua, tuoi, tue; je, jij, jou, jouw, jullie)                           | fr, it, nl         |
| 5   | Länge                    | bis 30 Zeichen Deutsch höchstens 1.8-mal so lang plus 6, darüber 1.5-mal plus 10                                                 | fr, it, nl         |
| 6   | Begriffe                 | Begriffe des Glossars übersetzt wie festgelegt, Namen unverändert                                                                | fr, it, nl         |
| 7   | Scharfes S               | kein scharfes S (U+00DF, auch nicht das grosse U+1E9E)                                                                           | alle, auch Deutsch |
| 8   | Langer Gedankenstrich    | kein U+2014                                                                                                                      | alle               |
| 9   | Vollständig              | jeder deutsche Schlüssel übersetzt, nur mit `I18N_REQUIRE_COMPLETE`                                                              | fr, it, nl         |
| 10  | Rechtstexte              | Englisch hat sie immer; mit `I18N_REQUIRE_COMPLETE` auch die anderen, mit `I18N_REQUIRE_LEGAL` aktuell                           | en, fr, it, nl     |
| 11  | Französische Leerzeichen | geschütztes Leerzeichen vor ":" und "%", keins vor "?", "!" und ";"                                                              | fr                 |

Wie streng sie sind:

- **Im Test** (`pnpm test`) schlägt jede Prüfung fehl. Dazu prüfen die Tests der API die Stempel: Jede
  Übersetzung im Code hat einen Stempel mit ihrem aktuellen Wert, Englisch ist aktuell, und die Dateien
  sind, was `i18n:stamp --check` erwartet.
- **Beim Speichern, beim Import und in `i18n:apply`** sind 2, 7 und 8 harte Fehler. Französische Leerzeichen
  korrigiert die Console dabei selbst. Die Prüfungen 3 bis 6 erscheinen als Hinweise.
- **Bei der KI** sind 2 bis 8 und 11 harte Fehler, dazu die Regel, dass keine neuen Links, E-Mail-Adressen
  oder Zahlen dazukommen. Im Demo-Modus entfallen 3 bis 6.

Die Prüfungen 3 bis 6 und 11 sind Faustregeln und irren sich manchmal. Für solche Fälle gibt es
**Ausnahmen** in `packages/shared/src/i18n/allowlists/<Sprache>/<Gruppe>.ts`, pro Prüfung eine Liste von
Schlüsseln, jeder mit einem Kommentar, warum die Prüfung hier falsch liegt. Gruppe `a` sind die Abschnitte
`core`, `admin`, `ai`, `translations`, `email` und `pdf`, Gruppe `b` `hosting`, `cloudflare`, `websites` und
`mail`, Gruppe `c` `billing`, `cloud`, `storage`, `phone`, `media` und `uptime`. Eine Ausnahme für einen
Schlüssel, den es nicht mehr gibt, lässt den Test fehlschlagen.

Zwei Variablen machen die Tests strenger. Beide nehmen `1` oder `true` (dann Französisch, Italienisch und
Niederländisch) oder eine Liste wie `fr,it`:

- `I18N_REQUIRE_COMPLETE`: Jeder Text muss in diesen Sprachen übersetzt sein (Prüfungen 9 und 10). CI setzt sie
  nicht: Neue Texte dürfen zuerst nur auf Deutsch und Englisch kommen.
- `I18N_REQUIRE_LEGAL`: Die Rechtstexte müssen in diesen Sprachen übersetzt und aktuell sein. CI setzt
  `I18N_REQUIRE_LEGAL=1`.

CI prüft ausserdem mit `pnpm --filter @weblion/web check:chunks`, dass jede Sprache im Web in einem eigenen
Teil liegt und keine Texte von E-Mails und PDF in den Browser kommen.

## Rechtstexte

Die Rechtstexte sind `ai.notice.title` und `ai.notice.text`, der Datenschutzhinweis der KI-Funktionen
(`LEGAL_KEYS` in `packages/shared/src/translations.ts`). Für sie gilt:

- **Nie maschinell übersetzt.** "Mit KI übersetzen" lässt sie aus, "KI-Vorschlag" lehnt sie ab, und der Import
  überspringt KI-Texte für sie. Übersetzt werden sie von Hand, im Code oder unter Admin > Übersetzungen.
- **Nie veraltet angezeigt.** Ändert sich der deutsche Text, zeigt die Console in den anderen Sprachen bis zur
  neuen Übersetzung den englischen Text, wenn er aktuell ist, sonst den deutschen. Das gilt für Übersetzungen
  im Code und für Änderungen im Admin-Bereich. Auch eine Änderung am deutschen Text im Admin-Bereich macht die
  Übersetzungen veraltet. Die Übersicht warnt, solange eine Sprache nicht aktuell ist.
- **Vom Inhaber geprüft.** Vor dem Einschalten der KI prüft der Inhaber den Hinweis in allen fünf Sprachen,
  am besten mit einer Anwältin oder einem Anwalt (siehe [ai.md](ai.md#vor-dem-einschalten)).

## Was nicht übersetzt wird

- **Fehlermeldungen der API** bleiben Englisch, denn sie gehören zur öffentlichen Schnittstelle. Die Console
  übersetzt im Browser: Netzwerkfehler, die allgemeinen Codes (`unauthorized`, `forbidden`, `not_found`,
  `rate_limited`, `internal_error`), Fehler des Reverse Proxy (502, 503, 504) und alle Codes der KI und der
  Übersetzungen. Alle anderen Fehler, etwa zur Prüfung von Eingaben, zu Konflikten oder von Providern, zeigen
  die englische Meldung der API.
- **Logs des Servers**, die Namen der Aktionen und die Details im Audit-Log, die Antworten im API Explorer.
- **Gespeicherte Texte** bleiben in der Sprache, in der sie geschrieben wurden: Positionen auf Rechnungen,
  Namen von Servern, Domains und anderen Ressourcen.
- **QR-Rechnung:** Die Mitteilung "Rechnung <Nummer>" bleibt in jeder Sprache Deutsch, damit der Abgleich mit
  der Bank nicht von der Sprache abhängt. Den Zahlteil gibt es auf Deutsch, Englisch, Französisch und
  Italienisch. Niederländische Rechnungen haben den englischen Zahlteil.

Für später denkbar (siehe [Roadmap](roadmap.md)): ein Katalog für die Fehlercodes der API, damit sich auch
diese Meldungen übersetzen lassen.

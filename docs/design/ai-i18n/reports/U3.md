## Deviations from the plan and the designs

1. **`report.ts`** holds the usage report, the errors page and the per-organization counts instead of `usage.ts`, so
   `usage.ts` stays the reservation and accounting module; `checkBudgetWarning` is in `usage.ts` as plan 2.4 names it.
2. **SSE disconnect** is detected on `reply.raw` `close`, not `req.raw` `close`: in Node the request emits `close` once its
   body is read, the response only when the connection ends. Tested with a real HTTP client (`cancelled`).
3. **`reserve()`** (F's code, U3's file): a month whose budget is used up (`spent >= budget`) now refuses every request,
   also demo requests with an estimate of 0, which before passed when spent equalled the budget exactly. F's tests stay
   green.
4. **`checkBudgetWarning`** sends nothing while the budget is 0 (that setting refuses every request on purpose; it would
   otherwise mail "exhausted" every month).
5. **Chat texts are redacted**: user and assistant messages from the browser pass the new `redactSecrets()` (exact secrets
   and patterns of ai 11.2 without the 4,000-character cap; `redactText` now calls it). ai 5.2 promises that a key pasted
   into the chat never leaves the console; 9.2 did not say where.
6. **`ConsoleReader`** has an optional fifth argument `{ liveGuard }`. Features pass `liveReadAllowed(orgId)`, so each live
   read of a feature counts against the 30 per minute; the chat counts per live tool call (6.4 step 9) and passes none.
7. **DNS records** (`get_dns_records`) are cut at 200 items instead of 50 (a zone check needs the whole zone; the
   20,000-character cut still applies).
8. **`propose_dns_record`**: a type the provider does not accept (`dnsRecordTypes`) makes the proposal `textOnly`
   (ai 8.4 step 5) instead of refusing it (step 2 said both).
9. **Admin explain of an audit row** checks `assertOrgData` for the row's organization, a `resourceType = 'org'`
   resource and the organizations named in its details (ai 10.1 named the first two; the third matches the
   blocked-customer filter of 8.3).
10. **Demo assistant** proposes the missing DMARC record when there is one, else the first missing record (ai 14 said the
    first missing one; plan 8.4 scenario 1 expects DMARC, and on Muster AG DKIM comes first).
11. **Usage report for an earlier month**: `budget` is computed from that month's cost with the current budget setting,
    `reservedMicros` 0.
12. **`AiService.chatPingMs`**: public field so tests shorten the 15 s ping; no env variable.
13. **Mock**: `fallbackTo.toolUsesBefore` (tool calls of the declined part) and `parseSse()`.

## Known gaps

- After an unparseable tool input the call is re-issued once (ai 6.4 step 4); text the failed attempt had already streamed
  stays in the browser, because `AiSseEvent` has no event to retract it.
- Feature routes (not the chat) do not abort the Claude call when the browser goes away; it ends at the answer or the turn
  timeout.
- The live-read window is per process (as designed); with several API processes the organization gets 30 per process.
- `get_billing_summary` for viewers: whether they read billing depends on `billing:read` of the role; the tool reports
  `forbidden` when the route refuses.

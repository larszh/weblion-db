## Deviations from the plan, with reasons

1. **More files in `components/ai/`** (all U4's by plan 11): `cards.tsx` (the three switch cards and the consent dialog; ai 12.4 put them into `bits.tsx`, which would have grown past 650 lines), `feature-dialogs.tsx` (DNS check, audit summary, server analysis, product texts), `ask-assistant.tsx` (the dashboard menu), `assistant-bus.ts` (opens the panel from the dashboard; the plan limits `AiProvider` to the proposal and the explain handler), tests `cards.test.tsx` and `features.test.tsx`. Also `pages/admin/ai.test.tsx` next to U4's page (not in the matrix; please treat as U4's).
2. **Additive hook parameters** in U4's own `lib/api/ai.ts`: `useAiStatus(enabled = true)`, `useAdminAiSettings(enabled = true)`, `useSaveAiSettings(onSuccess?, errorToast = true)`, `onSuccess` callbacks on the key, test and switch mutations, `aiFeatureOn(status, feature)`, the `ChatMessage` type and the limits `CHAT_*`. The admin and reseller switch mutations pass `errorToast: false` (the cards and the consent dialog show the error, including 409 `ai_platform_locked` / `ai_reseller_blocked`); the decline mutation keeps the toast.
3. **The unverified confirmation is inline** in the proposal card (`role="alertdialog"`, title, text, cancel, "Trotzdem öffnen") instead of a modal: it works inside the assistant's sheet and renders in the static tests ("rendered open from state"); a Radix dialog renders into a portal and is empty under `renderToStaticMarkup`.
4. **`ai.audit.showEntry` is unused**: the audit API has no lookup by id (`modules/audit/routes.ts`), so a summary cannot link to one entry. The highlights show as text.
5. **Seller dialog**: the picker lists products in the viewer's language; picking one fills the service's name and description in the customer's billing language (`profile.effectiveLocale`), because the service text ends up on the customer's invoices (the same idea as the invoice editor in O14).
6. **Session hint** (`ai.assistant.sessionHint`) is shown once at the top of the message list instead of in the footer, so the footer stays two lines at 390 px.
7. **Chat storage**: the chat is written to `sessionStorage` whenever no answer is streaming (not on every text chunk); a reload during a stream loses only that turn, and a stored streaming answer loads as "Angehalten".
8. **Server activity**: only failed provider actions get "Erklären" (as ai 12.5 says); the audit list on that tab gets none, because explaining audit rows needs `audit:read`, which server readers may lack.
9. **AiProvider reads the organization by slug** with its own `useQuery` on `qk.orgBySlug(slug)` (the same key and request as `OrgLayout`), enabled only once signed in, because it sits outside `OrgProvider`; it reads `MeDto` from the cache only (`useCachedMe`), so the login and invitation pages start no request.

## Known gaps

- Not run in a browser (no dev server for this unit); 390 px and dark mode follow the existing tokens and patterns (cards below `md` on the errors tab, wrapping filter grid, tables scroll inside their card, sheet full screen below `sm`). Screenshots and the end-to-end scenarios are the integrator's (8.4, 8.5).
- The API routes are U3's and were coded against `packages/shared/src/ai.ts` and ai 5 and 9 to 10 (all tests use stubbed `fetch` or static state). In particular: `GET /admin/ai/errors` query names `page`, `perPage`, `feature`, `status`, `source`; `OrgAiDto.switch.by === null` while never switched on (O34).
- Until U2 lands, `localizeError` returns the API's English message, so AI errors show in English; the data notice preview and the notice dialog use `t()` and show overrides once U2's runtime serves them.

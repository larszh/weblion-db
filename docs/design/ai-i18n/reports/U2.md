## Build bullets (plan 6 U2)

### Web runtime: done

- `lib/i18n-loader.ts` (new): one dynamic import per locale (`import('@weblion/shared/i18n/<l>')`), marker check
  (`I18N_CHUNK === 'wl-i18n-chunk:<l>'`), one retry after 500 ms, per-locale cache, `loadBundles`, `loadDictionary`
  (fr/it/nl = `{ ...en, ...l }`, German never loaded for them), `loadOverrides` (A1 with `cache: 'no-store'`,
  `credentials: 'omit'`, `If-None-Match`, cached copy `localStorage['wl-i18n-overrides:<l>']`, 304 keeps it, 200
  replaces it, errors keep it; with a cached copy the boot does not wait and revalidates in the background, without
  one it waits at most 1,500 ms and applies late values when they arrive). A `createI18nLoader(deps)` factory makes
  it testable. The loader imports only the web aggregators.
- `lib/i18n.tsx`: lazy, exported names and types of plan 2.9 kept. State lives in a store (`createI18nStore`) that
  the provider reads with `useSyncExternalStore` (server snapshot = client snapshot) and tests drive directly. Merge
  order fr override > fr bundle > en override > en bundle; `boot.dictionary` is honoured (so `withI18n` works
  unchanged); `setLocale` keeps the old dictionary until the new one is loaded, rejects on failure, writes
  `wl-locale` and `wl-locale-v = '2'` and `html[lang]`; `applyOverride` updates memory and the cached copy (ETag
  dropped); `applyOverrides` likewise for a whole locale; `useChangeLocale` toasts `language.loadFailed`;
  `hasKey` answers from the dictionary on screen.
- `main.tsx`: `await bootI18n()` before the first render (top-level await), the bilingual boot error with a reload
  button (listener attached in code, CSP safe), and `vite:preloadError` reloads once (guarded by a timestamp, so a
  chunk missing for another reason cannot loop).
- `apps/web/index.html`: static spinner inside `#root` (no text, `aria-label` = product name, fades in after
  150 ms, dark variant under `html.dark`, no animation with `prefers-reduced-motion`).
- `lib/format.ts`: every Intl call through `intlLocale(locale)`; `formatDuration` day unit per locale
  (`T`, `d`, `j`, `g`, `d`).
- `lib/api-errors.ts`: `localizeError(err, t)` with the five rules of i18n 7 and every code of plan 2.10 (AI codes
  with `ai.error.limit.<kind>`, i18n codes with their details, generic codes, proxy pages, everything else the
  English API message). Keys built at runtime are checked for existence (a code without a key keeps its English
  message). Extra exports `aiErrorKeys`, `aiErrorCamel`, `translationJobErrorKey` (for the test; U1 may use the
  last one).
- `src/test/i18n.tsx`: unchanged signature and content (the lazy provider honours `boot.dictionary`).

## Deviations from the plan, with reasons

1. `formatMailSize(bytes, locale, { unlimited?: string })` replaces `{ zeroUnlimited?: boolean }` instead of taking
   `t`: the caller passes `t('mail.units.unlimited')`. No production caller used the option, so the callers in
   `pages/admin/mail.tsx`, `pages/mail/bits.tsx`, `mailboxes.tsx` and `overview.tsx` needed no change (they already
   pass the UI locale, which now goes through `intlLocale`). Keeps `units.ts` free of the i18n runtime.
2. Units on invoice lines (`unitForInterval(interval, t)`) are in the UI language: the web has no dictionary of the
   invoice language (only the product name and description have per-language data, plan O14). Lines keep their text
   once added, as before.
3. `Mailer` gained `translator(locale): Tr` (in `mail/types.ts`, U2) so `sendInvitationMail` translates the role
   with overrides; the invitation's data shape is unchanged.
4. `renderMail(template, data, locale, tr?)`: `tr` is optional (default: the compiled catalog with the fallback
   chain), so `test/mail.test.ts` and scripts keep working; `MailService` always passes the I18nService translator.
5. `toBillingProfileDto` takes a fourth argument `effectiveLocale` (computed by `billingLocale`), because the DTO
   builder is synchronous; `billingLocale(db, orgId, profile?)` takes the loaded profile to save a query. Both live in
   `modules/billing/dto.ts` (i18n 9 allowed `settings.ts` or `invoices.ts`; `dto.ts` is where both DTOs are built and
   it is U2's).
6. `lib/i18n.tsx` exports more than plan 2.9 lists (all additive): `createI18nStore`, `composeDictionary`,
   `profileLocaleDecision`, `initialLocale`, `storedLocale`, `storedLocaleIsCurrent`, `storeLocale`,
   `useOptionalLocale`, the storage constants, and `bootI18n(loader?)` has an optional loader for tests.
   `I18nStore.receiveOverrides` exists next to `applyOverrides` so a background revalidation never drops the ETag
   that the loader just stored (the plan's 8.4 scenario expects a 304 on the next load).
7. The boot waits at most 1,500 ms for overrides without a cached copy by racing a timer instead of
   `AbortSignal.timeout(1500)`: an aborted request could not "apply them when they arrive" (i18n 5.3). The request
   itself is given up after 15 s.
8. `LanguageMenuItems` and the login menu use Radix `RadioGroup`/`RadioItem` (`menuitemradio` with `aria-checked`)
   instead of plain `MenuItem`s, so the current language is exposed to screen readers, not only as a check icon.
9. Account page: the language is a full-width card above the profile card (the five tiles need the width); the
   page grid got `grid-cols-1` below `lg`, because an auto track took the max-content width of the tiles (840 px at
   390 px, found in a browser check).
10. Invite page: the language field sits in the new-account form with its hint, and the corner menu is hidden there
    (one control instead of two that do the same).
11. PDF download: `Content-Disposition` gets an ASCII `filename` plus `filename*=UTF-8''...` when the translated
    name has non-ASCII characters (an override such as "Rëchnung" would otherwise make the header invalid). Plain
    ASCII names keep today's header exactly (`billing.test.ts` checks it).
12. `PATCH /auth/me` records `auth.profile_update` on every call (`changed` may be empty), following "every write
    route is audited".
13. The invitation accept records the new account's language in the existing `member.join` entry
    (`accountCreated: true, locale`) instead of a new action.
14. `localizeError` rule 2 also tries `ai.error.<camelCode>.<details.reason>` before the plain key when such a key
    exists (none today), a harmless generalization of the `ai_limit` rule.
15. `Flag` without a provider (tests) labels in English.

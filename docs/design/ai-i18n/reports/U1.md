## Deviations from the plan and designs

1. `estimate` is `estimate(ctx, scope, failed?)` and returns `{ dto, plan, selection }` (plan 6: `estimate(pairs,
   locales)`): B2, B3 and B7 need the plan and the selection counts from the same pass, and the translator is U1's
   alone. The selection is `selectPairs(i18n, scope, failed?)`; `batches(pairs)` takes pairs with their German text.
2. `validateItem` takes `text: unknown`, so "no entry for this item" (reason `missing`) is expressed in the input.
3. Batches keep catalog order inside a locale and are cut only by the 50-key and 8,000-character rules, not at
   section boundaries ("consecutive keys of one section stay together" read as: never reordered).
4. Estimate counts: `keys` and `keptManual` count cells; `legal` and `skipped` count keys (once per key, as the
   texts "{count} Rechtstexte" and "Keys without letters" read). A legal key is counted when the selection would
   have picked it in at least one requested locale.
5. A4 `placeholder_mismatch` adds `details.lineBreaks: { expected, actual }` when only the line breaks differ (the
   lists would be empty otherwise). Import and `i18n:apply` treat line breaks the same way.
6. Import of an overrides file: manual rows become `reviewed = markReviewed || the file's reviewed flag` (i18n 16.2
   says `markReviewed`), so an export and re-import between installations keeps a reviewed manual text reviewed; AI
   rows keep origin and flag as specified. The overrides export leaves out orphans as well as demo rows (nothing can
   apply a removed key).
7. Built-in glossary terms keep their term: a `PATCH` that renames one answers 400 `bad_request` with `details[0].path
   = 'term'` (no new code, plan 2.10); the start seeds built-in terms by their term and would bring the old one back.
   The editor shows the term read-only for built-in terms.
8. Runner: before each batch a job whose `demo` differs from the current `availability('translations').demo` stops
   with `ai_not_configured` (a demo job must not continue against a real key and save real texts as demo rows, nor
   the reverse). An unexpected error of ours inside a batch stops the job with `ai_failed` (no own code exists).
9. `seedI18nDemo` skips under vitest (change request 1). `insertI18nDemo(db)` does the work.
10. Audit of A8 and A15: `resourceType: 'translation'`, `resourceId: null` (many cells at once; plan 4.3 names
    `'settings'` only for `i18n_style`).
11. `TranslationJobDto.inputTokens` sums input, cache read and cache write tokens; `outputTokens` is the output.
12. B6 for an unknown job id answers 404 `not_found`.
13. Cell editor from `md` up: an expanded row under the edited row of the table instead of a floating popover
    (i18n 17.2). It never overflows at narrow desktop widths and needs no positioning code; below `md` it opens at
    full card width under the tapped language row as specified.
14. After a job ends (job detail or the polled overview), the page loads A1 for the UI language and its English
    fallback and calls `applyOverrides`, so the console's own texts change at once (i18n 12.1 step 8).
15. "Mit KI übersetzen" is shown with `platform:i18n:write` and `platform:ai:use`; while AI is not available the
    dialog explains why (`featureOff`, `notConfigured` with the link), as i18n 17.1 says.
16. `ai_upstream` `request` inside a job is logged with the `ai_usage` id (the row holds the request id); the AppError
    of `structured()` does not carry the request id.
